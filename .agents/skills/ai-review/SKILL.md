# AI Review

评审 PaddleFleet 代码的实际行为和跨模块影响。优先级、评论格式和发布策略由调用方决定；本 skill 只提供仓库级评审规则。

## 规则加载

加载本 skill 后、开始评审前，读取 `.agents/skills/ai-review/references/` 目录下的全部 Markdown 文件。必须包含 [基础规则](references/base-rules.md)；其他文件均为扩展规则，不按变更路径跳过加载。根据各规则声明的适用路径和触发条件决定是否应用。

## 评审流程

1. 阅读 PR 描述和完整 diff，确认变更目标、影响范围及用户可见行为。
2. 使用 `rg` 追踪定义、调用方、配置入口、实现和测试；跨模块变更必须检查两端契约。
3. 对照完整函数和相关测试验证候选问题，确认可复现或有明确代码证据后再报告。
4. 评论应指出具体位置、影响、触发条件和修改方向；不报告无依据的猜测、纯风格偏好或泛化建议。

更具体的扩展规则优先于基础规则；规则冲突且无法由代码或仓库约定判定时，向维护者确认。

## 基本原则

- 正确性、安全和兼容性优先于格式与命名。
- 分布式、算子和数值路径必须同时检查前向/反向、边界条件及回退路径。
- 行为变化必须有与风险匹配的单卡或多卡测试。
- 本 skill 和规则使用简体中文；GitHub 评论语言遵循调用方配置。
